# TEAMIX Firestore 규칙 테스트

## 실행

Node.js 22 이상과 Firestore 에뮬레이터가 지원하는 Java(21 권장)가 필요합니다.
저장소 루트에서 `npm install` 후 `npm run test:rules`를 실행하세요.
이 명령은 demo-teamix-rules 프로젝트의 로컬 Firestore 에뮬레이터에서만 테스트합니다.
에뮬레이터를 별도 실행하려면 `npm run emulators:rules`를 사용하고,
다른 터미널에 FIRESTORE_EMULATOR_HOST=127.0.0.1:8080을 설정한 뒤
`npm run test:rules:unit`를 실행하세요. 환경변수 설정 문법은 셸에 따라 다릅니다.
프로덕션 배포는 자동 수행하지 않습니다. 테스트 데이터를 실제 프로젝트에 넣지 않습니다.

## 구현 범위

- 기존 firebase.json의 Flutter 설정을 유지하고 rules/indexes 및 에뮬레이터 설정을 추가했습니다.
- 사용자 프로필, 모임, 회원, 가입 요청, 초대, 소모임, 신청, 초안 수정, 공개, 비공개 선호 접근 규칙입니다.
- 참가 신청/취소는 신청 문서와 활동 카운터를 같은 배치/트랜잭션으로 변경해야 합니다.
- 응답 변경은 인원수를 유지하고 responseVersion만 +1 합니다. 카운터 분기는 updatedAt을 변경하지 않습니다.
- owner와 admin은 같은 운영 권한이지만 owner 신원 변경/삭제는 금지합니다.
- 후기, 대표자 이전, 고정 배치, 필수 역할은 이번 범위에서 지원하지 않습니다.
- 소모임 정원과 팀 수는 공모전 범위에 맞춰 최대 100으로 제한합니다.
- 명부에는 uid/groupId/닉네임/역할/가입일만 저장합니다. 개인 프로필과 응답은 별도 경로입니다.
- 재가입 이력 정책은 미포함입니다. 승인된 요청을 가진 탈퇴자의 재요청은 아직 지원하지 않습니다.

## 서버 연동 계약: 서버 코드는 이번 변경에 포함하지 않음

편성 엔드포인트는 반드시 Firebase ID 토큰을 검증하고 Admin SDK로 소모임의 groupId와
요청자의 현재 memberships 역할(owner/admin)을 확인해야 합니다.
앱에서 보낸 역할이나 groupId를 신뢰하면 안 됩니다. Admin SDK는 규칙을 우회합니다.
현재 Python 서버가 이 계약을 만족하는지와 무관하게 이 규칙이 서버를 보호해 주지는 않습니다.
서버 구현 시 응답/설정 버전 확인 후 drafts를 생성하고 enginePublic에는 public 결과만 저장합니다.
초안의 sourceResponseVersion/sourceSettingsVersion/revision은 서버가 초기화해야 합니다.
초대 확인 엔드포인트도 인증 및 요청 제한 후 허용된 모임 소개와 inviteId만 반환해야 합니다.
이 PR은 위 두 엔드포인트나 기존 Flutter 화면의 Firestore 직접 쓰기를 구현하지 않습니다.

## 규칙과 앱 검증의 경계

Firestore 규칙에는 임의 길이 배열을 반복 검증하는 기능이 없습니다.
teamCapacities 내부 전체 항목, editedTeams/publications.teams의 누락·중복·정원·중첩 공개 필드,
닉네임 사본과 재계산 요약의 일치 검증은 이번 축소 설계대로 앱/편성 서버 책임입니다.
규칙은 권한·최상위 허용 필드·응답 형식·버전·포인터 원자성을 검증합니다.
운영자가 직접 공개 배열을 쓰므로 악의적 운영자의 잘못된 팀 데이터까지 차단하지는 못합니다.
강한 무결성이 필요하면 공개를 서버 명령으로 옮기거나 팀/배정을 문서 단위로 정규화해야 합니다.
수동 수정에서 비공개 선호 위반 검사는 하지 않습니다.
비공개 선호 철회는 배열 항목 삭제 또는 문서 삭제이며 이력을 남기지 않습니다.
모든 소모임 참가자는 실제 회원 문서를 유지해야 공개 결과를 읽을 수 있습니다.
collectionGroup 규칙은 동일 이름의 컬렉션 전체에 적용되므로 memberships/joinRequests를 다른 용도로 쓰지 마세요.
에뮬레이터는 프로덕션 복합 인덱스 필요 여부를 완전히 재현하지 않으므로 인덱스 배포 후 별도 확인이 필요합니다.

## 검증 상태

이 변경 작성 환경에서는 npm 의존성 설치, Java 에뮬레이터, 규칙 컴파일 및 테스트를 실행하지 않았습니다.
위 로컬 명령으로 성공을 확인한 뒤 직접 머지하세요. 테스트 통과를 주장하지 않습니다.
